Task: find what static analysis missed in one deployable unit, or across the whole system. The first message is TOML: [task] says what to look for and lists the repositories; [unit] or [[unit]] describes what static analysis found; each [[known]] is a risk or connection already found, which you must not report again.

Look for what a careful reviewer would report:
- risks: security gaps (identity, permissions or tenancy taken from what a caller sends; missing or wrong access checks; secrets exposed), consistency gaps (side effects before a transaction commits; data shared without an owner; message or API contracts that differ between the two sides), and availability gaps (single points of failure, missing timeouts or retries on calls that block a request, listeners with no handling for messages they cannot process);
- connections: calls, messages, data stores or external systems a unit uses that no fact links it to. Tracing, logging, metrics, a service registry or a config server is infrastructure, not a connection: do not report one.

Read with the tools in small, targeted calls, several independent ones in one turn when you can, asking for numbered lines. A tool answer longer than 1,500 characters is cut and you need another call for the rest, so ask for only the lines you need: a line range, a grep with -n, a head. Read the code before you report anything, and report only what the lines you cite show.

Answer once, through the answer tool, as TOML in this form, the most important first, at most 10 entries in all; an answer with no entry says you found nothing, which is a good answer when the code shows nothing:

[[risk]]
title = "..."           # a title of 5 to 7 words
finding = "..."         # what the code does, in one or two sentences of 20 to 60 words
consequence = "..."     # what can happen because of it, in one or two sentences of 22 to 60 words
impact = "medium"       # high, medium or low, by what an attacker or a failure could do to data or availability
confidence = "high"     # high, medium or low
units = ["service:com.shop:orders-service"]   # the units it is about, by their IDs in [task]

[[risk.evidence]]       # at least one for each entry, at most 8
lines = "Shop:orders-service/src/main/java/Orders.java:12-30"   # repo:path:from-to, at most 40 lines
quote = "public void place(Order order) {"                     # one line of that range, copied exactly
shows = ["place"]                                              # the names in that range your text uses

[[connection]]
from = "service:com.shop:orders-service"   # a unit's ID, as [task] lists them
to = "external-system:Stripe"               # a unit's or element's ID, or a new external-system:<name> or database:<name>
interaction = "messaging"    # http, messaging, database, mail or other
description = "..."          # a description of 3 to 12 words: what the unit uses it for
technology = "RabbitMQ"

[[connection.evidence]]
lines = "..."
quote = "..."
shows = ["..."]

The repository is the name before the first colon, as [task] lists it; a service's folder inside a repository is part of the path. Every class, method, field, path, header, setting or topic the title, finding or consequence names must be in the shows of some evidence. Name no tool, file or technology the evidence does not show, not even to say it is missing. Before you answer, check for each risk that the title has 5 to 7 words.
