# Lantern run, scoring and test-set commands

The build and test commands every issue needs (full check, quick check, formatting, one module, local database, Maven mirror) are in `CLAUDE.md`, Commands, which also states the requirements. Run everything from the repo root. A real model costs money, so run it only with the user's go-ahead.

- Launch a local run in one step (checks JDK 21, Docker and git, checks the database port is free, starts the database, builds the jar if missing, runs `analyze`): `scripts/launch.sh --llm-properties <llm.properties> [--mirror-properties <local.properties>] [--system <name>] [--title <title>] [--set <property>=<value>]... [<name>=]<path>...`; `--set lantern.llm.roles.<role>=<model>` serves one role with another model of the settings file for that run; `--db-only` only starts the database, and `--yes` skips the cost question (required when not at a terminal). Stop it with `scripts/teardown.sh` (`--purge` also deletes the data volume). Both respect `COMPOSE_PROJECT_NAME`; options are in `--help`.
- Sandbox builds download only from the Maven repositories in `lantern.sandbox.maven-repositories` (Maven Central by default; see `docs/adr/0023-configurable-maven-repositories.md`). To allow others, list them all in a properties file and add it to the app's: `--spring.config.additional-location=file:<repositories.properties>,file:<llm.properties>`.
- Run the real-provider LLM test (costs money; only with the user's go-ahead), with `ANTHROPIC_API_KEY` already exported: `LANTERN_LLM_REAL_TEST=true LANTERN_LLM_REAL_TEST_MODEL=<model> ./mvnw verify -pl lantern-llm -am`
- Run the app (needs the local database): `./mvnw install -DskipTests && ./mvnw spring-boot:run -pl lantern-app`
- Analyze repositories end to end, one command for register, snapshot, build, extract, summarize, compose and render (needs the local database, Docker and the LLM settings of `docs/adr/0009-llm-configuration.md` in a properties file outside the repository; a real model costs money, so only with the user's go-ahead): `./mvnw install -DskipTests && java -jar lantern-app/target/lantern-app-*-exec.jar --spring.config.additional-location=file:<llm.properties> analyze [--system=<name>] [--title=<title>] [<name>=]<path>...`. The repositories form one named system, by default named after the folder they are all in; a repository belongs to one system, and `remove --system=<name> <repo>...` (instead of `analyze`) takes it out. It writes `workspace/documents/<system>/<snapshot>/<repo>.html` (Architecture Explorer), `<repo>.brief.html` (Executive Brief) and `<repo>.c4.html` (the `report-specs/c4-model-sequence-diagrams` report), and `_system.c4.html` (the same report for all repositories of the system as one system, titled by the system's title); see `docs/adr/0016-end-to-end-analysis-run.md`, `docs/adr/0031-report-spec-renderer.md`, `docs/adr/0044-c4-views.md` and `docs/adr/0071-named-systems.md`.
- Score a Lantern system report against a development set's reference (free, no LLM; `docs/adr/0072-scoring-harness.md`): `node lantern-web/scripts/score.mjs <report .c4.html or .json> testsets/<set> [--run <run.json>] [--out <prefix>]` writes `<prefix>.scorecard.json` and `<prefix>.scorecard.md` (default prefix: the report's path without `.html`). `run.json` is what `analyze` writes beside its documents: each role's provider and model, and the run's calls and cost. Compare two scorecards side by side: `node lantern-web/scripts/score.mjs compare <a.scorecard.json> <b.scorecard.json> [--labels <a>,<b>] [--out <file.md>]`. Without Node 24 installed, use `lantern-web/target/node/node`, which the build installs.
- Measure extraction coverage, which reference items of a set the extracted facts back before linking (free, no LLM; `docs/adr/0089-extraction-coverage.md`): `node lantern-web/scripts/coverage.mjs <extracted.jsonl.gz> testsets/<set> [--out <prefix>]` writes `<prefix>.coverage.json` and `.md`; `extracted.jsonl.gz` is what `analyze` writes beside its documents. Check a set's map `testsets/<set>/coverage.json`, with the set's checkout for its citations: `node lantern-web/scripts/coverage.mjs check testsets/<set> [~/workspace/lantern-test-projects/<set>]`. `scripts/score-testsets.sh` runs it on every set it scores, and the full check on project-0 (into `lantern-app/target/project-0/`).
- Run Lantern on the development sets project-1 to project-4 and score each (sets set up as below; starts the local database through `scripts/launch.sh`; a real model costs money, so only with the user's go-ahead): `scripts/score-testsets.sh --llm-properties <llm.properties> [--mirror-properties <local.properties>] [--role <role>=<model>]... [--tier <tier>=<model>]... [--label <name>] [--compare-with <earlier label>] [<set>...]`. It writes `workspace/scores/<label>/<set>.scorecard.json` and `.md`, the report and `run.json` in `<set>/`, and with `--compare-with` `<set>.compare.md`; `--score-only` scores the newest reports without analyzing (the sets need not be set up). `--fake-llm` instead of `--llm-properties` runs every role on a free fake model (Spring profile `fake-llm`; models `fake` and the priced `fake-priced`), so a whole run costs nothing. It refuses the held-out sets project-5 to project-7 unless `--held-out` is given, which is only for Phase 2's real-model acceptance (`docs/design.md`, Test sets).
- Run a set twice with the fake model, the second time with Summarize on another (priced) fake model, score both and compare them (free): `./mvnw verify -pl lantern-app -am -Dlantern.test.set=$HOME/workspace/lantern-test-projects/project-4 -Dit.test=TestSetScoreIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`; it writes `lantern-app/target/test-sets/<set>/`. A held-out set fails it unless `-Dlantern.test.held-out=true` (`docs/design.md`, Test sets).
- Run that pipeline twice on any Maven repository with the fake model, checking the second run makes no LLM calls, and write the calls and estimated tokens a real run would use to `lantern-app/target/end-to-end/`: `./mvnw verify -pl lantern-app -am -Dlantern.test.repo=<absolute path> -Dit.test=EndToEndIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
- Set up the synthetic test set project-0 at its pinned commit (private repository, so git needs GitHub credentials; see `docs/adr/0029-synthetic-test-set-project-0.md`), then build each of its repositories in the sandbox: `testsets/project-0/setup.sh && ./mvnw verify -pl lantern-sandbox -am -Dlantern.test.project0=$HOME/workspace/lantern-test-projects/project-0 -Dit.test=Project0BuildIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
- Set up the synthetic test set project-8 (FleetCare) at its pinned commit (private repository, so git needs GitHub credentials; `docs/adr/0029-synthetic-test-set-project-0.md`, amendment for #285): `testsets/project-8/setup.sh [destination]` makes its 15 repositories under `~/workspace/lantern-test-projects/project-8/` and puts its expected answers in `expected/` there. Analyze and score it with `scripts/score-testsets.sh --fake-llm [--mirror-properties <local.properties>] project-8` (free), and compare the scorecard with the committed baseline `testsets/project-8/baseline.scorecard.md`.
- Set up an open-source test set, project-1 to project-4 (development) or project-5 to project-7 (held-out: set them up only for the work that may touch them, `docs/design.md`, Test sets): `testsets/project-<n>/setup.sh [destination]` clones each repository in its `pins.txt` into `~/workspace/lantern-test-projects/project-<n>/` and checks out the pinned commit (format: `docs/adr/0029-synthetic-test-set-project-0.md`, amendment for #251). `./mvnw verify` checks, without network, that each committed reference in `testsets/<set>/reference/` is valid for the C4 report spec and describes the pinned commits (`lantern-web/test/test-set-references.test.mjs`).
- Check claim identity on every fact of a development set's snapshot (`docs/adr/0090-key-attributes.md`; analyzes it with the fake model, free; set up as below; writes facts and claims per predicate to `lantern-app/target/claims/<set>.tsv`): `./mvnw verify -pl lantern-app -am -Dlantern.test.claims-set=$HOME/workspace/lantern-test-projects/project-8 -Dit.test=ClaimIdentityIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`. project-0's end-to-end test in the full check runs the same check.
- Check the extractors' facts on project-0 (set up as above; reads the repositories from git, builds nothing): `./mvnw verify -pl lantern-extract -am -Dlantern.test.project0=$HOME/workspace/lantern-test-projects/project-0 -Dit.test='Project0*IT' -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
- Check the deployable units on project-0 (set up as above; builds each repository in the sandbox): `./mvnw verify -pl lantern-link -am -Dlantern.test.project0=$HOME/workspace/lantern-test-projects/project-0 -Dit.test=Project0DeployableUnitsIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
- Check the gateway routes of project-1, project-2 and project-4 (each set up with its `testsets/project-N/setup.sh`; reads the repositories from git, builds nothing; writes the lines to `lantern-link/target/gateway-routes/`): `./mvnw verify -pl lantern-link -am -Dlantern.test.projects=$HOME/workspace/lantern-test-projects -Dit.test=GatewayRoutesIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
- Check value resolution on project-8, deployment environments as views included (set up with `testsets/project-8/setup.sh`; reads the repositories from git, builds nothing, no Docker): `./mvnw verify -pl lantern-link -am -Dlantern.test.projects=$HOME/workspace/lantern-test-projects -Dit.test=Project8ValuesIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
- Check the Redis data stores of the test sets project-1 and project-4 (set up as in their `testsets/project-N/setup.sh`; reads the repositories named in `pins.txt` from git, builds nothing, no Docker): `./mvnw verify -pl lantern-link -am -Dlantern.test.projects=$HOME/workspace/lantern-test-projects -Dit.test=Project1And4RedisIT -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false -Dfailsafe.failIfNoSpecifiedTests=false`
