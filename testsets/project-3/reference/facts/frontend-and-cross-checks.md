# project-3 (MediaHub): web app, and the cross-checks behind the flows and risks

Scope: mediahub-frontend-ui (HEAD `acefeda`, 2026-03-24, "feat: user profile"), checked against the backend facts in `services.md` and `edge-config-deployment.md`. "FE" = mediahub-frontend-ui; paths under `FE/src/app/` are written `app/…`.

## 1. Web app (`FE`)

**Tech.** Angular **21.2** standalone app, Bootstrap 5.3 and bootstrap-icons from `node_modules`, RxJS 7.8, TypeScript 5.9, Vitest (`FE/package.json:13-34`; styles and scripts `FE/angular.json:27-34`). Generated by Angular CLI 21.2.2 (`FE/README.md:3`).

**How it runs.** Only `ng serve` (port 4200, `FE/README.md:10-13`; verification: was `:47-55`, which is the e2e section) with a dev proxy sending `/api` to `http://localhost:8080` (`FE/proxy.conf.json:1-7`, used by the development serve configuration, `FE/angular.json:60-72`). There is no Dockerfile, nginx config or production API URL, and compose does not run it (`edge-config-deployment.md` §5). All API calls use relative `/api/v1/...` paths.

**Routes** (`app/app.routes.ts:13-23`): `''` Home, `login`, `register`, and behind `authGuard` `catalog`, `catalog/:id`, `dashboard`, `subscriptions`, `history`. The guard only checks that a token is in localStorage (`app/core/guards/auth.guard.ts:5-15`, `app/core/services/auth.service.ts:69-71`). Navbar links: Catalog, Subscriptions, Dashboard, Login, Get Started (`app/shared/navbar/navbar.ts:24-36`). No admin screen exists; `isAdmin()` (`auth.service.ts:73-75`) is not used by any route.

**Auth.** `AuthService` posts to `/api/v1/auth/login` and `/api/v1/auth/register` and expects `{token, user}`, kept in localStorage (`app/core/services/auth.service.ts:23,35-53,62-67`). `jwtInterceptor` adds `Authorization: Bearer <token>` to every request when a token exists (`app/core/interceptors/jwt.interceptor.ts:3-16`, registered in `app/app.config.ts:11`). Login form fields email + password (`app/features/auth/login.ts:108-109,120`); register form username, email, password, confirmPassword (`app/features/auth/register.ts:111-112,131`).

**Hard-coded content.** The Subscriptions page lists plans BASIC 9.99, PREMIUM 14.99, **ULTRA** 19.99 in the component (`subscription.ts:100-104`); the backend plans are BASIC, PREMIUM, **PRO**, with the price sent by the client (`SS Plan.java:3-7`). `Subscription` model has `planName` with `ULTRA` (`app/core/models/subscription.model.ts:1-9`). Thumbnails fall back to `https://picsum.photos/...?random=<id>` in catalog, detail, dashboard and history (`catalog.ts:42`, `media-detail.ts:53`, `dashboard.ts:74`, `history.ts:29`); since the backend has no `thumbnailUrl`, the browser always loads them from Lorem Picsum.

**Conclusion.** Through the gateway the web app can reach only the media catalogue reads and the user list. It cannot sign in or register, so every guarded page is unreachable unless a token is planted in localStorage; and once there, the dashboard, history and subscription calls fail. Nothing in the app registers a watch or creates a subscription.

## 2. Flow cross-checks

- **Create a subscription** (the main business call; `INFRA/Makefile:73-76`, Insomnia line 188): client → gateway `subscription_route` → subscription-service `POST /api/v1/subscriptions` → Feign `GET /api/v1/users/{id}` on user-service via Eureka (`SS UserClient.java:8-13` → `US UserController.java:37-41`) → save in `mediahub_subscription` (`SS SubscriptionServiceImpl.java:26-46`). Response 200 with `ApiResponse` (the controller returns the body directly, no `ResponseEntity`, `SubscriptionController.java:21-26`).
- **Verify access** (`GET /api/v1/subscriptions/user/{id}/active`; `SS SubscriptionController.java:49-54`): one query; no call to other services. No other service calls it: media-service never checks a subscription before serving media (`MS` has no client), so "verification of access rights" (`SS/README.md:4`) is only offered, not enforced.
- **Register a watch** (`POST /USER-SERVICE/api/history/watch/{u}/{m}` via the discovery locator, or directly on :8081): user-service → Feign `GET /api/media/{id}` on media-service (`US MediaServiceClient.java:7-11`) → fails (media-service serves `/api/v1/media/{id}`; the unmatched path raises `NoResourceFoundException`, which its `@ExceptionHandler(Exception.class)` turns into 500, `MS GlobalExceptionHandler.java:50-56`; verification: was "404") → `RuntimeException` → 500 (`WatchHistoryServiceImpl.java:22-29`). Nothing is saved.
- **Media info** (`GET /api/v1/subscriptions/media-info/{id}`; `INFRA/Makefile:77-78`): subscription-service → load-balanced WebClient → media-service `GET /api/v1/media/{id}` → returned nested (`SS SubscriptionServiceImpl.java:86-94`). A 404 from media-service makes `retrieve()` throw `WebClientResponseException` → 500 (not run).
- **Start-up**: each service fetches `{name}/{profile}` from the config server (`spring.cloud.config.uri`, fail-fast with 5 retries in US/MS/SS), the config server reads the YAML from the mounted folder (compose, `native`) or clones GitHub (`git`, the default), then the service registers in Eureka with a 5 s lease renewal (`CR/application.yml:7-10`); the gateway resolves `lb://` names from its registry fetched every 5 s (`CR/application.yml:5`). Compose orders it with health checks (`INFRA/docker-compose.yml:30-31,44-48,112-118`). The config server itself also registers in Eureka (`CS ConfigServerApplication.java:10`, `CS pom.xml:40`).
- **Exposed through the gateway.** Discovery locator + no security means `http://<host>:8080/CONFIG-SERVER/user-service/default` would return `user-service.yml` as stored, including the datasource URL, user and `${DB_PASS:password}` (the config server does not resolve placeholders by default, so the default password itself is shown; not run). `GET /actuator/gateway/routes` is used by the Makefile and Insomnia (`INFRA/Makefile:79-80`), so the gateway actuator is reachable from outside; with `management.endpoint.gateway.enabled: true` (`CR/api-gateway.yml:22-25`) Spring Cloud Gateway's actuator also accepts `POST /actuator/gateway/routes/{id}` and `/actuator/gateway/refresh` (framework behaviour; not run). The gateway's local `application.yaml:35-39` exposes all actuator endpoints (`env`, `heapdump`, …); the config server's `CR/api-gateway.yml:26-29` narrows that when it is applied (remote properties take precedence).
