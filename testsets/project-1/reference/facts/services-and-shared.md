## 1. Shared modules (libraries, not runtime units)

- **common-core**: only constants, `ROLE_ADMIN`/`ROLE_USER`, `X-Requested-With` (`common-core/src/main/java/com/example/common/core/constant/SecurityConstants.java:3-15`) and cookie names `BFF_SESSION`, `JSESSIONID` (`.../SessionConstants.java:3-11`).
- **common-web** (auto-configured, `common-web/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports:1`; `CW/config/CommonWebAutoConfiguration.java:6-9` scans `com.example.common.web`): `GlobalExceptionHandler` returns RFC 9457 Problem Details, maps `DataIntegrityViolationException` to 409 and hides details under `prod` (`CW/exception/GlobalExceptionHandler.java:43-50,100-104,146-160`); `TrailingSlashFilter` at highest precedence strips a trailing slash, which is how the gateway's `/profile` → `/api/` lands on `@RequestMapping("/api")` (`CW/filter/TrailingSlashFilter.java:35-54`); logback profiles default/json/loki, Loki push to `${LOKI_URL}` (`common-web/src/main/resources/logback-spring.xml:21-64`). Dependencies include Zipkin and Prometheus registries (`common-web/pom.xml:61-77`). Used by bff and, through common-security, by the three domain services (README `README.md:231-245`).
- **common-security** (auto-configured, `common-security/src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports:1-2`; `META-INF/spring.factories:1-2`):
  - `ResourceServerDefaultsEnvironmentPostProcessor` adds `issuer-uri=${KEYCLOAK_ISSUER_URI:http://localhost:8080/realms/my-realm}` and `audiences=${API_AUDIENCE:template-api}` as lowest-priority defaults (`CS/ResourceServerDefaultsEnvironmentPostProcessor.java:28-43`).
  - `ResourceServerSecurityAutoConfiguration`: servlet only, `@EnableMethodSecurity`, default chain unless a service defines one: CSRF off, health/prometheus and `security.resource-server.public-endpoints` permitted, everything else authenticated, JWT resource server with `KeycloakJwtAuthenticationConverter` (`CS/ResourceServerSecurityAutoConfiguration.java:35-74`; property `CS/ResourceServerSecurityProperties.java:11-17`).
  - `KeycloakJwtAuthenticationConverter` maps `realm_access.roles` to `ROLE_<ROLE>` authorities and uses `preferred_username` (or `sub`) as the name (`CS/KeycloakJwtAuthenticationConverter.java:17-47`).
  - `OpenApiAutoConfiguration` / `OpenApiConfigFactory` (springdoc setup; not read in detail).
- **common-test**: Testcontainers helpers for Keycloak and Redis, test scope only (`common-test/src/main/java/com/example/common/test/KeycloakTestContainer.java`, `RedisTestContainer.java`; `service-parent/pom.xml:46-60`).

## 2. profile-service

- Spring MVC, port **8082**, virtual threads (`PR/application.properties:1-2`). Dependencies: restclient, springdoc webmvc, common-security, oauth2-client, data-jpa, PostgreSQL driver, Flyway (`profile-service/pom.xml:18-56`).
- Data: `profile_db` on PostgreSQL (`${DATABASE_URL:jdbc:postgresql://localhost:5433/profile_db}`), `ddl-auto=validate`, Flyway with `baseline-on-migrate` (`PR/application.properties:7-20`). Schema `user_profiles` (id, user_id unique, names, email unique, mobile, gender MALE/FEMALE, age, enabled) and `pending_registrations` (id = profile id, confirmation_token unique, token_expiry, confirmation_type EMAIL/MOBILE, created_at) (`PR/db/migration/V1__init.sql:4-32`); V2 drops the old `password_hash` column (`PR/db/migration/V2__drop_password_hash.sql:1-6`). Entities: `P/model/UserProfileEntity.java:11-64` (`enabled` defaults to false, `:62-64`), `P/model/PendingRegistrationEntity.java:31-50` (`@MapsId` to the profile, raw `confirmationToken`).
- Outbound config: `keycloak.admin-service.url=${KEYCLOAK_ADMIN_SERVICE_URL:http://localhost:8084/api}`; OAuth2 client registration `internal` (client `internal-client`, secret default `my-internal-secret`, `client_credentials`, provider `keycloak` by issuer) (`PR/application.properties:22-31`); RestClient timeouts 2 s / 10 s (`:33-35`); registration token expiry 24 h and confirmation URL `${REGISTRATION_CONFIRMATION_URL:http://localhost:4200/confirm}` (`:37-39`). Actuator 9082 (`:41-45`), OpenAPI under `/api/public/api-docs` (`:47-49`), public endpoints `/api/public/**` (`:56-57`); springdoc off in `prod` (`PR/application-prod.properties:1-3`).
- **Inbound REST**
  - `ProfileController` `/api` (via gateway `/profile`): `GET` own profile by JWT `sub` (404 if none), `POST` create own profile (409 if exists), `DELETE` own profile (`P/controller/ProfileController.java:22-43`; `P/service/ProfileService.java:23-73`). *(Second pass)* `createProfile` takes `email` from the request body (`ProfileService.java:53-62`; `P/dto/UserProfileRequest.java:19-20`, only `@Email`) and never compares it with the token; the UI pre-fills it from the OIDC user but the field is editable (`angular-ui/src/app/features/profile/profile.component.ts:80`). `user_profiles.email` is unique (`PR/db/migration/V1__init.sql:16`) and `register` skips any email already present (`P/service/RegistrationService.java:103-106`).
  - `RegistrationController` `/api/public` (via gateway `/profile/public`, no token): `POST /register` always 201 with the same message, `GET /confirm?token=` (`P/controller/RegistrationController.java:37-78`).
  - `AdminProfileController` `/api/profile/admin` with `hasRole('ADMIN')`: `POST /users`, `DELETE /users/{userId}`, passing the caller's `Authorization` header on (`P/controller/AdminProfileController.java:12-33`). Through the gateway this is `/profile/profile/admin/users` (route `/profile/**` → `/api/**`, `gateway/src/main/resources/application.properties:15-19`).
- **Registration** (`P/service/RegistrationService.java`):
  - `register`: if any profile already has the email, log and return (no error, no email) (`:100-106`); else UUID token, expiry now + 24 h, persist a disabled profile and a pending registration in a `REQUIRES_NEW` transaction (`:108-118`; `P/service/RegistrationPersistenceService.java:41-68`, profile `userId` is a random UUID placeholder and `enabled(false)`, `:43-52`); a unique-email race is swallowed (`:113-118`); then `emailService.sendConfirmationEmail(email, <confirmation URL>?token=…)` (`:120-121`).
  - `confirm` (`@Transactional`): unknown token → 400, expired → 400 (`:133-141`); calls keycloak-admin-service to create the Keycloak user (username = email) with a password email (`:146-152`); sets the profile's `userId` to the Keycloak id and `enabled=true`, saves, deletes the pending registration (`:154-160`); any exception → 500 "Failed to complete registration" (`:165-168`).
  - Javadoc TODOs: no cleanup job for expired pending registrations, no rate limiting, no CAPTCHA (`:51-56`).
- **Email**: interface only (`P/service/EmailService.java:3-16`). The one implementation `LoggingEmailService` is `@Profile("!prod")` and only logs the confirmation URL (`P/service/LoggingEmailService.java:7-28`). Under `prod` no bean exists and the service fails to start, on purpose (`docs/PRODUCTION_CHECKLIST.md:41-51`).
- **Keycloak admin client** (`P/service/KeycloakAdminClient.java`): plain RestClient for `POST {adminUrl}/users` and `DELETE {adminUrl}/users/{id}` with the caller's bearer token (`:47-62`); second RestClient with `OAuth2ClientHttpRequestInterceptor` that attaches a client-credentials token of registration `internal` for `POST {adminUrl}/users/register` (`:38-45,78-93`). Token store is in memory (`P/config/SecurityConfig.java:36-63`). It calls keycloak-admin-service directly, not through the gateway (URL `http://keycloak-admin-service:8084/api` in compose, `compose.yaml:277`).
- **Admin user saga** (`P/service/ProfileService.java`): create = Keycloak user first, then profile, deleting the Keycloak user if the profile insert fails (`:79-107`); the admin-created profile never sets `enabled`, so it stays false (`:86-93` with the entity default). Delete = profile first, then Keycloak user; a Keycloak failure leaves an orphan and answers 500 (`:122-136`).

## 3. order-service

- Spring MVC, port **8083**, virtual threads (`OR/application.properties:1-2`); dependencies springdoc, common-security, data-jpa, PostgreSQL, Flyway (`order-service/pom.xml:16-41`).
- Data: `order_db` (`${DATABASE_URL:jdbc:postgresql://localhost:5434/order_db}`), validate + Flyway (`OR/application.properties:7-20`). Table `orders` with unique `order_number` and status check (`OR/db/migration/V1__init.sql:4-15`); V2 makes the timestamps `timestamptz` and adds `version` (`OR/db/migration/V2__order_audit_columns.sql:8-14`). Entity with auditing and `@Version` (`O/model/OrderEntity.java:14-57`); statuses CREATED…CANCELED (`O/model/OrderStatus.java:3-10`).
- Inbound REST `OrdersController` `/api` (via gateway `/orders`): `POST` creates an order with the given `orderNumber` and status CREATED; `GET` pages the caller's orders by `createdBy = sub` (`O/controller/OrdersController.java:23-41`; `O/service/OrderService.java:20-36`; `O/repository/OrderRepository.java:8-10`). `createdBy`/`updatedBy` come from the JWT subject through JPA auditing (`O/config/JpaAuditingConfig.java:23-39`). No endpoint changes an order's status.
- Public endpoints `/api/public/**` (only API docs) (`OR/application.properties:28-38`). Actuator 9083 (`:22-26`). No outbound calls besides PostgreSQL, JWKS and Zipkin.

## 4. keycloak-admin-service

- Spring MVC, port **8084** (`KR/application.properties:1-2`); `keycloak-admin-client` and common-security (`keycloak-admin-service/pom.xml:16-24`). No database.
- Keycloak Admin client: server `${KEYCLOAK_SERVER_URL:http://localhost:8080}`, realm `${KEYCLOAK_REALM:my-realm}`, client `admin-service-client`, secret default `admin-secret`, client-credentials grant (`KR/application.properties:8-13`; `K/config/KeycloakConfig.java:10-34`). The realm grants that service account `manage-users` and `view-users` (`keycloak/realm-config/realm-export.json:205-214`).
- **Inbound REST** `AdminController` `/api` (via gateway `/admin`) (`K/controller/AdminController.java:31-149`):
  - `POST /users` (`hasRole('ADMIN')`): creates an enabled Keycloak user, with a password when given; returns the new id (`:42-76`).
  - `POST /users/register` (`hasRole('INTERNAL_SERVICE')`): creates an enabled, email-verified user without a password, then asks Keycloak to email an `UPDATE_PASSWORD` action; a failure to send is logged and ignored, and 201 is still returned (`:100-134`). The gateway also blocks `/admin/users/register` with 403 (`gateway/src/main/resources/application.properties:62-66`).
  - `DELETE /users/{id}` (`hasRole('ADMIN')`) (`:136-148`).
- Javadoc says "only the confirmation token's BCrypt hash is temporarily stored" (`:92-93`), but profile-service stores the raw UUID token (`P/service/RegistrationPersistenceService.java:59-65`; column `PR/db/migration/V1__init.sql:24`).
- Actuator 9084, readiness without dependencies (`KR/application.properties:15-19`).
