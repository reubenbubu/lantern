# project-1 (Enterprise Spring Microservices Template): web edge, BFF and gateway

Pin read: `Enterprise-Spring-Microservices-Template` at `8f5cb6873691f8b67353c4924fb06f469c2ef4e4` (`8f5cb68`, 2026-09-21, "Merge branch 'enhancement/spring-boot-4.1-upgrade' into 'main'"). One repository, a Maven reactor plus an Angular app. Paths are relative to the repository root. Shorthands: `B/` = `bff/src/main/java/com/example/bff/`, `G/` = `gateway/src/main/java/com/example/gateway/`, `UI/` = `angular-ui/src/app/`.

## 1. Reactor and stack

- Root POM `microservices-parent`: Spring Boot parent **4.1.1**, **Java 25**, Tomcat overridden to 11.0.26 for CVEs (`pom.xml:6-11,18-24`). Modules: common-core, common-web, common-security, common-test, dependencies-bom, service-parent, bff, gateway, profile-service, order-service, keycloak-admin-service (`pom.xml:26-38`).
- `dependencies-bom`: Spring Cloud 2025.1.3, springdoc 3.1.1, keycloak-admin-client 26.0.12, nimbus-jose-jwt 10.10, Resilience4j 2.4.0, logstash encoder 9.0, loki4j 2.1.0 (`dependencies-bom/pom.xml:14-21`).
- `service-parent` (parent of bff, profile-service, order-service, keycloak-admin-service): spring-boot-starter-web, -security, -oauth2-resource-server, -actuator, Lombok (`service-parent/pom.xml:23-44`). The gateway does not use it; it is WebFlux (README `README.md:247,292`).
- One multi-stage `Dockerfile` for all five Java services, selected with `--build-arg MODULE=` (`Dockerfile:1-14`); build on `maven:3.9-eclipse-temurin-25` (`:16-45`), run on `eclipse-temurin:25-jre-alpine` as user `spring` (`:64-78`).

## 2. angular-ui (web app)

- Angular **^22.1.7** with Angular Material, RxJS 7.8, TypeScript ~6.0, Vitest and Playwright (`angular-ui/package.json:18-34`). Zoneless, standalone, `HttpClient` with one interceptor (`UI/app.config.ts:9-16`).
- Routes: `/login`, `/register`, `/confirm` (public) and, behind `authGuard`, `/dashboard`, `/profile`, `/orders` (`UI/app.routes.ts:4-45`). `authGuard` probes the session with `checkAuth()` and sends the user to `/login` on failure (`UI/core/guards/auth.guard.ts:5-17`).
- Every call goes to the relative base `/bff` (`angular-ui/src/environments/environment.ts:1-4`, `environment.prod.ts:1-4`). The interceptor adds `withCredentials` and `X-Requested-With: XMLHttpRequest`, and on a 401 (other than the `/bff/user` probe) navigates the browser to `/bff/login` (`UI/core/interceptors/auth.interceptor.ts:15-39`).
- AuthService: `GET /bff/user` to learn who is signed in (`UI/core/services/auth.service.ts:28-39`); `login()` sets `window.location.href = /bff/login` (`:41-43`); `logout()` submits a hidden top-level form `POST /bff/logout` with the `XSRF-TOKEN` cookie value as `_csrf` (`:58-75`).
- Feature services: profile `GET|POST|DELETE /bff/api/profile` (`UI/features/profile/profile.service.ts:12-31`); orders `GET /bff/api/orders?page&size&sort=creationTime,desc` and `POST /bff/api/orders {orderNumber}` where the order number is generated in the browser as `ORD-` + a random integer below 10000 (`UI/features/orders/orders.service.ts:25-41`); registration `POST /bff/public/profile/register` and `GET /bff/public/profile/confirm?token=` (`UI/features/register/register.service.ts:32-46`). The confirm page calls confirm with the `token` query parameter on load (`UI/features/register/confirm.component.ts:117-136`).
- The profile page pre-fills a new profile from the OIDC user (`sub`, `email`, `name`) and creates, shows or deletes it (`UI/features/profile/profile.component.ts:151-218`). The dashboard loads the profile and the orders (`UI/features/dashboard/dashboard.component.ts:105,112`).
- No UI calls any admin endpoint (no `admin` path in any feature service; checked `UI/features/*/*.service.ts`).
- Serving: dev server proxies `/bff` to `http://localhost:8081` with `changeOrigin` (`angular-ui/proxy.conf.json:1-7`). Container: built on `node:24-alpine`, served by `nginx:alpine` on port 4200 (`angular-ui/Dockerfile:6-24`). nginx serves the SPA with a strict CSP and proxies `/bff/` to `http://bff:8081/bff/` with `Host: localhost:8081` and `X-Forwarded-For` (`angular-ui/nginx.conf:1-54`, proxy at `:40-53`).

## 3. bff (Backend-for-Frontend)

- Spring MVC on port **8081**, virtual threads (`bff/src/main/resources/application.properties:1,6`). Dependencies: common-web, restclient, data-redis, oauth2-client, **spring-boot-starter-session-data-redis** (JSESSIONID in Redis), nimbus-jose-jwt, resilience4j-spring-boot4 (`bff/pom.xml:16-69`, Spring Session comment `:38-44`).
- OAuth2 client registration `keycloak`: client `bff-client`, secret default `mysecret`, authorization_code, redirect `{baseUrl}/login/oauth2/code/keycloak`, scopes openid/profile/email, issuer `${KEYCLOAK_ISSUER_URI}` (`application.properties:17-24`).
- BFF_SESSION cookie: HttpOnly, SameSite=Lax, `Secure` from `BFF_COOKIE_SECURE` (default false); session TTL 30 min; gateway URL `${GATEWAY_URL:http://127.0.0.1:8888}`; frontend URL; CORS origins; RestClient timeouts 2 s / 10 s; refresh buffer 60 s (`application.properties:26-60`). Actuator on 9081 (`:62-66`); Zipkin export (`:68-71`); circuit breaker `gateway` (window 10, 50 %, 10 s open, 4xx ignored) (`:73-82`).
- **Endpoints** (`B/controller/BffController.java`):
  - `GET /bff/user` returns the OIDC user from the Spring Security session (`:123-126`).
  - `GET /bff/login` redirects to `/oauth2/authorization/keycloak` (`:128-131`). *(Second pass)* `sendRedirect` with Spring Boot's default `server.tomcat.use-relative-redirects=false` gives an absolute `Location` built from the Host header, which nginx pins to `localhost:8081` (`angular-ui/nginx.conf:47-48`) and the dev proxy rewrites with `changeOrigin` (`angular-ui/proxy.conf.json:5`). The browser therefore leaves the `/bff` proxy for the OAuth2 steps and talks to the BFF's published port 8081 directly; the realm's only redirect URI for `bff-client` is `http://localhost:8081/login/oauth2/code/keycloak` (`keycloak/realm-config/realm-export.json:48-50`). Not run, but the callback URI alone fixes the browser-to-BFF hop.
  - `GET /bff/login/success` (Spring Security's success URL, `B/config/SecurityConfig.java:94-96`): copies access, refresh and ID tokens into a `BffSession`, stores it in Redis under a new UUID `jti`, removes the in-memory authorized client, issues a signed BFF_SESSION JWT cookie and redirects to the frontend (`:151-197`).
  - `POST /bff/logout`: loads the session for its ID token, deletes it in Redis, invalidates the HTTP session, clears both cookies and redirects to Keycloak's end-session endpoint with `id_token_hint` and `post_logout_redirect_uri=<frontend>/login` (`:230-291`).
  - `/bff/api/**` (GET, POST, PUT, DELETE, PATCH): needs the BFF_SESSION cookie, verifies it, loads the Redis session (401 otherwise), strips `/bff/api` and calls `${gateway}/<rest>` with `Authorization: Bearer <access token>` (`:293-326`).
  - `/bff/public/{service}/**` (GET, POST): rewrites `/bff/public/{service}/x` to `${gateway}/{service}/public/x` and calls it without a token (`:337-357`).
  - Both go through one Resilience4j `gateway` circuit breaker: 4xx/5xx are passed through, an open circuit gives 503, an unreachable gateway 502 (`:377-405`). The forwarded request carries only `Authorization`, `Content-Type`, `Accept` and `Accept-Language`; no `X-Forwarded-For` (`:407-430`).
- **Servlet session cookie** *(second pass)*: the repo calls it JSESSIONID throughout, but with Spring Session (`bff/pom.xml:38-44`) and no `server.servlet.session.cookie.name` in `bff/src/main/resources/application.properties`, Spring Session's default cookie name `SESSION` most likely applies; the explicit `JSESSIONID` clearing on logout (`BffController.java:278-284`) would then be a no-op, while `session.invalidate()` (`:254-257`) still ends the session. Not run.
- **Security chain** (`B/config/SecurityConfig.java`): strict CSP / no-referrer / deny framing (`:72-76`); `TokenRefreshFilter` before the username/password filter (`:77`); permitAll for `/bff/login`, `/bff/logout`, `/bff/public/**`, `/login/**`, `/oauth2/**`, `/bff/api/**`, `/error`, health and prometheus; everything else authenticated (`:78-93`); `oauth2Login` with default success URL `/bff/login/success` (`:94-96`); CSRF with a readable `XSRF-TOKEN` cookie, ignoring public and login paths (`:117-122`, `B/filter/CsrfCookieFilter.java:26-31`); entry point answers 401 to AJAX/JSON requests and redirects browsers to `/oauth2/authorization/keycloak` (`:152-183`); CORS for the configured origins with credentials (`:185-200`).
- **Session JWT** (`B/util/JwtUtils.java`): RS256 key from `BFF_JWT_SIGNING_KEY`; when blank, an ephemeral key in dev and a startup failure under `prod` (`:77-100`). Claims: issuer, subject, `jti`, issue time, **expiry = login + 30 min**, email, name (`:102-130`). `extractJti` checks signature, expiry and issuer (`:132-157`). The JWT is issued only at login (`BffController.java:184` is the only production caller).
- **Session store** (`B/service/SessionRedisService.java:24-41`): JSON `BffSession` under `bff:session:<jti>` with a 30-minute TTL on every save (`SessionRedisService.java:31-33`; JSON serializer `RedisConfig.java:26-35`; record `B/session/BffSession.java:33-39` holds principal, access token and expiry, refresh token, ID token, scopes, and deliberately no client secret, `:11-31`).
- **Proactive refresh** (`B/filter/TokenRefreshFilter.java`): only for `/bff/api/` (`:59,96-99`); if the access token expires within 60 s, takes a Redis lock `bff:session:<jti>:refresh-lock` (SET NX, 5 s TTL) (`:133-154`, `B/service/RefreshLockService.java:31-60`), posts `grant_type=refresh_token` with the client id and secret to Keycloak's token endpoint and saves the new tokens (`:200-238`); requests that lose the lock poll for up to 3 s (`:155-167`, `RefreshLockService.java:47,75-91`); an `invalid_grant` deletes the session unless another node already rotated it (`:186-198`).

## 4. gateway (API gateway)

- Spring Cloud Gateway **Server WebFlux** on port **8888** (`gateway/src/main/resources/application.properties:1`; `gateway/pom.xml:17`), springdoc webflux UI, oauth2 resource server, security, reactive Redis, Zipkin starter, Spring Cloud circuit breaker with Resilience4j, Prometheus (`gateway/pom.xml:17-95`).
- **Routes** (`application.properties:14-66`):

| id | predicate | filters | target |
|---|---|---|---|
| profile-service | `/profile/**` | StripPrefix=1, PrefixPath=/api, RequestRateLimiter 10/s burst 20 by `userKeyResolver`, CircuitBreaker `profileServiceCB` → `forward:/fallback` | `${PROFILE_SERVICE_URL:http://127.0.0.1:8082}` (`:15-26`) |
| order-service | `/orders/**` | same, `orderServiceCB` | `${ORDER_SERVICE_URL:http://127.0.0.1:8083}` (`:29-40`) |
| admin-service | `/admin/**` | same, `adminServiceCB` | `${ADMIN_SERVICE_URL:http://127.0.0.1:8084}` (`:43-54`) |
| block-internal-registration | `/admin/users/register`, order -1 | SetStatus=403 | `no://op` (`:62-66`) |

- Resilience4j defaults: window 10, 50 %, 10 s open, time limit 5 s (`:72-89`). Redis for the rate limiter (`:104-107`). Resource server: issuer `${KEYCLOAK_ISSUER_URI}`, audience `${API_AUDIENCE:template-api}` (`:112-117`). `gateway.rate-limiter.trusted-proxy-hops=${TRUSTED_PROXY_HOPS:0}` (`:120`). Actuator on 9888 (`:125-128`), tracing (`:133-135`), Swagger UI aggregating only the profile and order API docs (`:140-143`); springdoc off under `prod` (`gateway/src/main/resources/application-prod.properties:1-3`).
- Security (`G/config/SecurityConfig.java:10-43`): CSRF off; permitAll for `/*/public/**`, health, prometheus, Swagger and `/fallback`; everything else needs a valid JWT (`oauth2ResourceServer().jwt()`). The gateway checks the token only; it does no role checks and forwards the `Authorization` header unchanged (no header filters in the routes).
- Rate-limit key (`G/config/RateLimiterConfig.java:35-53`): `user:<principal name>` when authenticated, else `ip:<remote address>`, where the remote address is the TCP peer unless `TRUSTED_PROXY_HOPS` > 0 (`:23-41`).
- Fallback: `/fallback` answers 503 Problem Details with the original path (`G/controller/FallbackController.java:19-50`). Routes are declared only in properties (`G/GatewayApplication.java:5-16`).
