## Scope choices

- **System boundary.** One software system, APA-CRM, holding the web app, the gateway, the Eureka
  registry, the four services, three PostgreSQL schemas, Redis and the RabbitMQ exchanges and queue.
  crm-shared-lib is a library compiled into the services, not a container. Deployment holds only
  descriptors.
- **Runtime units.** Seven containers: CRM-Frontend, api-gateway, eureka-service, auth-service,
  main-service, file-service, notification-service. Eureka counts although Kubernetes switches it
  off, because both Compose files run it.
- **Data stores.** auth_db, main_db and file_db are separate stores (one per service; Kustomize puts
  them in one PostgreSQL instance, Compose in three). Redis is one store, written by auth-service and
  read by the gateway.
- **Messaging.** Each producing service's topic exchange is its own element (`main-service.events`,
  `file-service.events`, `auth-service.event`), plus the queue `notification-service.send-message`
  that main-service reaches through the default exchange. Queues behind the exchanges are listed in a
  table, not drawn.
- **People.** Two: organization member and invited user. There are no fixed roles in code; an
  "administrator" is any member whose custom role grants the rights, so it is not a separate person.
- **External systems.** Only Gmail SMTP takes part in a user request. Docker Hub, JitPack, Prometheus
  and Grafana are build or operations tooling and are left out (stated on the context page).
- **Flows.** Six sequences: sign-in and an organization request, create an organization, invite a
  member, task reminder, real-time notification, password reset.
- **Decisions, risks, unknowns** sit at the end of the context page, a stopgap until lantern#249.
  There are no ADRs; decisions are observed in code, with rationale only where a README states one.
- **Not built or run.** Everything comes from reading the code and descriptors. Claims that depend on
  runtime behaviour are worded "probably".

## Files

- `facts/*.md`: the first pass's cited facts, by area (edge and deployment; Auth, File and
  Notification; Main and shared lib). Kept as written; where the second pass found them wrong,
  `verification.md` says so.
- `verification.md`: the independent second pass: what was checked, corrections, additions,
  judgement calls.
- `scripts/build-data.mjs` builds the data; `scripts/validate.cjs <schema> <data>` validates it
  against the report spec's schema plus cross-reference rules; `scripts/embed.cjs <template> <data>
  <out>` writes the HTML; `scripts/render.mjs <html> <outdir> [#hash...]` walks every page in
  headless Chrome and screenshots.
